Mismatch cause memo (paper chat item F)
  Some sk coefficients held by the firmware lie outside canonical form 0..q-1 (offset table above).
  The evaluation folds those coefficients mod q and searches among 0..q-1 candidates, but fqmul is a Montgomery
  reduction, so fqmul(a,b) and fqmul(a+q,b) are equal only mod q, and the stored 16-bit
  pattern can differ. The rate of difference depends on the distribution of b (= ciphertext NTT coefficients)
  and so varies per pair — hence 2~3% per pair, and 9.2% for pair 32.
  If the candidates are laid out with the actual offset of that coefficient, the correct candidate matches the firmware value
  bit for bit and the rate becomes 0%. However, the offset requires knowing the correct key, so this is not an attack but
  an **upper bound** (paper chat decision: no 2-representation version at 4x cost; stated explicitly as oracle).
